本文描述项目的技术栈、模块划分、数据流与安全边界，面向希望参与开发或审阅实现的读者。

公开文档只做架构级说明，不包含接口地址、请求头、签名算法或官方客户端反编译内容。

## 数据流

```mermaid
flowchart LR
    A[扫码 / 相册 / NFC / 手动输入] --> B[解析设备标识]
    B --> C[探测设备与套餐]
    C --> D[确认页: 套餐/支付通道优先，定位并行]
    D --> E[解锁并创建会话]
    E --> F[使用中页面]
    F --> G[前台同步服务]
    G --> H[设备结算与支付状态]
    H --> I[本地历史（带账号归属）]
    I --> J[账单匹配：只读订单详情 + 小票流水]
    J --> K[账单与优惠缓存到 SQLite]

    L[登录 / 添加账号] --> M[账号保险库]
    M --> N[切换账号]
    N --> A
    M --> O[设置页账号卡片]
    O --> P[账号资料 + 余额 + 小票]
    O --> Q[通用小票充值]
    Q --> R[创建官方虚拟订单]
    R --> S[支付宝 SDK 支付]
    S --> T[服务端订单状态核验]
    T --> P
```

关键点：

1. 扫描结果先解析为设备标识，再向官方服务探测设备详情。
2. 设备解析成功后后台预取套餐与支付通道；确认页优先展示本机缓存并在后台刷新，套餐与定位并行获取，套餐就绪即可浏览，定位就绪后才能解锁。确认页就绪后会后台预绑定当前支付通道，点击“开始使用”时只在通道变化或预绑定失败时补绑；解锁成功后先发布状态，再把确认设备记录异步落盘。设备就绪轮询由“解锁加速”设置控制：默认“保守”在前 2 秒按 250ms、之后回落到 1s；“不启用”恢复 1.13.1 之前的点击时绑定 + 固定 1s；“激进”前 3 秒按 100ms、之后 250ms，点击时若预绑定仍在途则不等待；“丧心病狂”在此基础上并行探测 `machine/device_is_start`，前 3 秒按 50ms、之后 100ms。15 秒总超时不变，激进/丧心病狂的预绑定失败会在后台补绑一次。
3. 套餐与支付方式按“设备 + 当前账号 `localId`”缓存 7 天，最多 50 条；命中先展示旧数据并后台刷新，刷新结果不改变当前确认页，避免价格与选中项跳变；解锁报错时清空该设备缓存。
4. 解锁成功后写入本地会话，并启动 `WaterSyncService`；会话记录创建时的账号 `localId`。
5. 前台服务轮询设备状态，触发结束、结算和支付查询。
6. 会话阶段与最终结果写入 SQLite，按账号隔离，供历史页展示和导出。
7. 历史页在读取本地记录后，对最近 90 天的记录按结算订单号读取只读账单；账单匹配到的优惠、实付和通用小票信息随记录缓存。更早的记录在打开详情或下拉刷新时按需请求。
8. 账单实付采用官方“实付款”口径；小票抵扣作为优惠明细展示，不重复从实付扣减。小票流水按订单号补充店铺、点数与本金/赠送；流水缺失时以账单抵扣为准并标注。
9. 账单同步有并发与批量上限；失败保留旧账单，未匹配不会用本地用量冒充金额。应用重启时，如果存在进行中的会话，会恢复前台服务。
10. 设置页的账号卡片独立加载资料与资产；失败时保留上次快照。
11. 通用小票充值从小票店铺或流水页进入：加载面额与店铺可用支付渠道，创建官方虚拟订单后调用支付宝 SDK；客户端不自行签名支付串，也不把 `9000` 当作最终成功，必须通过服务端订单状态或订单详情确认。

## 状态管理

- 页面状态以 `StateFlow` 和 Compose `State` 为主，控制器不直接持有 Activity。
- `AppGraph` 在 `Application` 中创建，作为轻量手动 DI 容器。
- `AppController` 维护应用级登录态与登录目标（首次登录、添加账号、失效重登）。
- `AssetController` 监听当前账号 `localId`，加载资料/余额/小票并维护资产快照；按 `localId` 去重，避免资料刷新触发循环请求。
- `HistoryController` 管理当前账号的历史读取、90 天账单批量同步、单条按需同步、缓存与重试状态，以及不持久化的筛选条件；它不创建、取消或支付订单。设置页导入成功后调用 `refresh`，复用同一套账单匹配流程。
- `TicketRechargeController` 是应用级充值状态机：加载面额/渠道、创建订单、准备支付、等待支付宝、核验结果；使用账号代次与 `localId` 丢弃旧请求，未知结果只允许重新查询，不自动重付。支付串只存在于控制器内存，不进入 UI 状态或本地存储。
- `HistoryFilter` 是不依赖 Android 的纯筛选策略：时间窗口、设备/状态/小票/金额条件和搜索都在这一层组合。`HistorySummary` 在筛选后的可见列表上计算原价合计、纯数字用量、可换算总水量、平均单价与覆盖率；平均单价分别按用量口径和水量口径统计。`HistoryUiState.records` 始终保存完整记录，`HistoryScreen` 派生可见列表和统计卡；账单同步、重试、删除与 CSV 仍使用完整列表。
- `WaterConversion` 是不依赖 Android 的全局换算策略：解析纯数字用量与带 L/mL 的水量，在展示时换算为 mL 和杯数。历史、接水页和通知共用同一套格式化逻辑；设置修改后不写回历史记录，而是由 UI 即时重算。未配置换算时不改变任何原有展示。
- `WaterSessionManager` 维护当前会话，并负责启动/结束前台服务。
- `Diagnostics` 是应用级诊断 facade：所有构建默认记录关键事件；`ScanController`、`ConfirmController`、`WaterSyncService` 与网络拦截器通过 `DiagSink` 写入同一 trace。`DiagWriter` 单协程异步落盘并维护内存列表，`DiagStore` 按天 NDJSON 存储、按天数与总字节清理，`DiagnosticsController` 提供筛选、统计、导出与设置给诊断页。
- 会话阶段、支付结果和错误信息集中保存在 `WaterSession`，避免多个页面各自推断。
- 支付查询有超时上限；超时后进入“支付状态未知”，不会无限轮询或自动重试扣款。

## 多账号与资产

### 账号保险库

- `AccountStore` 在现有 DataStore 中保存一个 JSON 账号列表和当前 `active_account_id`。
- 每个账号包含本地 `localId`、服务端 `serverId`、昵称/别名、头像 URL、脱敏手机号、加密手机号、加密 token、失效标记与最近使用时间。
- token 与完整手机号使用 AndroidKeyStore 的 AES-GCM 密钥分别加密；`localId` 是历史与资产快照的主键。
- 旧版本的单 token 会在首次启动时原子迁移为一条待同步账号；同步资料后补全昵称、头像与手机号。
- 添加账号时按手机号/服务端用户 ID 合并，避免同一账号重复保存；合并时迁移历史记录。
- 会话失效只标记账号并清空内存 token，不自动删除 token 密文；用户可重新登录或删除账号。
- 删除账号会同时删除该账号的资产快照、接水历史与待确认充值订单。

### 资产加载

- 资料与余额并行加载；余额点数大于 0 时再分页拉取按店铺的小票列表。
- 通用小票按 `localId` 保存最近一次成功快照；刷新失败时继续显示旧快照。
- 小票明细页按店铺展示总额/本金/赠送；点击店铺进入流水页并分页加载，`type==100` 显示为正，其他显示为负。
- 头像使用 Coil 3 加载，使用独立的普通 OkHttp 客户端，不携带登录 token 或签名头。

### 账号切换限制

- 接水会话处于进行中（使用中/结束中/结算中）时，拒绝切换、删除或退出账号。
- 切换账号会重置扫码状态；正在进行的网络刷新按代次/账号校验，旧结果不会写入新账号。
- 会话失效回调会比对“请求实际使用的 token”与当前 token，避免旧请求误伤刚切换的账号。

## 本地存储

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 账号 token（可多个） | DataStore + Android Keystore | 每个账号单独 AES-GCM 加密，密钥不出 Keystore |
| 账号资料 | DataStore | `localId`、服务端 ID、昵称/别名、头像 URL、脱敏手机号、加密完整手机号、失效标记 |
| 当前账号 | DataStore | `active_account_id`，决定请求使用的 token 与历史归属 |
| 资产快照 | DataStore | 每个账号一份资料/余额/小票汇总，刷新失败时兜底 |
| 待确认充值订单 | DataStore | 按账号 `localId` 保存店铺、订单号、金额、点数与创建时间，2 小时后过期；不含支付宝支付串、token 或支付结果原文 |
| 主题、动态取色、悬浮底栏、演练模式、一键解锁、跳过设备信息、解锁加速、资产隐藏、水量换算 | DataStore Preferences | 本机设置；水量换算全局生效，清除后恢复原始用量 |
| 当前接水会话 | DataStore Preferences | JSON 序列化，带创建时的账号 `localId`，供前台服务恢复 |
| 套餐与支付方式缓存 | DataStore Preferences（独立 `plan_cache` 文件） | 按设备与账号 `localId` 缓存；最长 7 天、最多 50 条，超出淘汰最旧；命中先展示、后台刷新 |
| NFC 标签映射 | DataStore Preferences | 标签 ID → SN、设备名、商品 ID |
| 接水历史与账单缓存 | SQLite `pangguai_history.db` | 订单号、金额、阶段、错误、时间、`account_id`，以及账单原价/优惠/实付、店铺/设备、小票抵扣与同步时间；账单 JSON 与记录同生命周期 |
| 调试请求日志 | 内存 | 仅 Debug，最多 100 条，退出进程即丢失；响应中的 token/手机号/姓名/证件号/头像地址会脱敏 |
| 解锁耗时 | 内存 | Debug 最多 20 条；诊断日志中的解锁阶段随 trace 持久化 |
| 诊断事件与接水 trace | `filesDir/diagnostics/{events,traces,crashes}/YYYY-MM-DD.ndjson` | 默认保留 7 天、上限 10 MB；按天写入，读取时按 traceId 取最新；日志开关关闭后停止写入，清空或删除账号时删除 |
| 诊断导出缓存 | `cacheDir/diagnostics/exports/` | 单 ZIP（TXT+JSON+README），最多 5 个 |

`allowBackup=false`，系统备份不会带走 token、历史或映射。卸载应用会删除本地数据。账号合并时历史记录会迁移到合并后的 `localId`；删除账号会删除该账号的历史与资产快照。主动退出并选择保留记录时，账号条目会清除 token 并标记为已退出，历史继续保留；重新登录同一手机号会沿用原 `localId`。CSV 导入在同一事务内按订单号去重写入当前账号，导入不完整或无效的行会跳过并计数。

## 网络与安全边界

- 网络层统一通过 OkHttp 拦截器附加登录态与设备信息，并对需要风控的请求计算签名。
- 构建所需的 API 凭据由 `secrets.properties` 或 CI Secret 注入 `BuildConfig`，不进入源码仓库。
- token 与完整手机号使用 Android Keystore 中的 AES-GCM 密钥加密；账号列表只保存密文与脱敏手机号。
- 设备标识使用本机 Android ID 的哈希，不读取 OAID。
- 会话失效由统一响应拦截器识别：仅当请求实际使用的 token 等于当前 token 时，才把对应账号标记为失效并回到登录流程；登录/验证码请求被排除。
- 头像加载使用独立的普通 OkHttp 客户端，不附加登录态或签名头；图片请求只会访问资料中返回的头像地址。
- 更新检查使用另一个独立的普通 OkHttp 客户端访问 GitHub Releases API，不附加登录态、设备信息或官方请求签名；只在进入主界面后检查一次，失败保持静默。
- 应用不集成广告、统计或推送 SDK；业务请求只用于官方服务，头像请求用于资料中的图片地址。
- 历史页的账单匹配只读取订单与通用小票流水，不创建、取消或支付订单；账单缓存随历史记录按账号隔离，删除记录、清空历史或删除账号时一并删除。
- 通用小票充值会创建官方虚拟订单、读取支付渠道并调起支付宝 SDK；客户端只透传服务端生成的支付串，不保存或打印完整 `orderInfo`，也不使用客户端密钥签名支付。支付成功以服务端订单状态为准。
- 支付宝 SDK 为闭源 AAR，仅在用户主动充值时拉起；支付过程由支付宝 App 或 SDK H5 页面处理，本应用不采集银行卡、支付密码或支付宝账号。
- 所有构建都会把网络请求的 method/path/status/耗时与脱敏响应预览写入诊断日志，不保存请求体、请求头与查询参数；完整 cURL 视图只在 Debug/诊断构建的内存中保留。
- 诊断日志只保存在本机，不自动上传；响应中的 token/手机号/证件号/定位/SN/IMEI 等字段会脱敏，非 JSON 响应不保存原文。诊断包导出前会提示可能包含设备名称、订单号与响应片段。
- 定位在扫码页已授权时静默预热，确认与下单流程读取风控参数；坐标仅在本机内存缓存 5 分钟，不写入磁盘、不保存位置历史。

## 构建类型

- `debug`：可调试、debug 签名，记录 Debug 级诊断事件与完整 cURL 视图，演练模式默认开启。
- `release`：R8 + 资源压缩，正式签名；默认记录 Info+ 关键事件与 4 KB 响应预览。
- `diagnostic`：由 release 派生，R8 + 资源压缩 + 正式签名 + 同包名/同 versionCode；`versionName` 加 `-diagnostic`，应用名显示“（诊断）”；记录 Debug 级事件与 16 KB 响应预览，但不开放 token 导入、演练模式默认关闭。`initWith(release)` 不会复制 `isShrinkResources`，构建脚本显式设置。

## 非目标

以下内容不在当前范围内：

- BLE 设备解锁。
- 绕过定位、实名或风控校验。
- 自动补缴、自动重试支付或代扣。
- 修改账号资料、上传头像、通用小票退款、绑定或换绑手机号。
- 社交、会员、广告与推送运营。
- 公开官方接口、签名算法或反编译材料。

## 关于页流体背景

- 仅 Android 13（API 33）及以上使用 AGSL RuntimeShader 绘制 OS3 流体头部；Android 12 使用纯色 surface，不创建 shader。
- 效果限制在头部区域，约 30fps；应用退到后台、滚出头部或系统关闭动画时暂停，避免持续 GPU 开销。
- 着色器与浅/深配色改编自 compose-miuix-ui（Apache-2.0）；构造失败时回退为纯色。
