## 真机验收清单

建议在每次较大改动或发版前执行。测试时使用最小套餐，避免产生不必要的费用。

1. 连接设备，确认 `adb devices` 可见；安装 Debug 包。
2. 从旧版本升级：确认旧 token 迁移后仍保持登录，旧接水记录回填到当前账号。
3. 完成免责声明、短信登录，并验证重启后自动登录。
4. 扫描真实设备二维码，在诊断页确认 `isBluetooth`、故障码、套餐和支付通道。
5. 碰一次 NFC 标签，确认标签解析、首次绑定，以及重启后映射仍然存在。
6. 保持演练模式走一次确认页，核对请求参数、签名是否存在和套餐信息。
7. 关闭演练模式，用最小套餐真实解锁；记录订单号、同步标识和支付单号，核对账单。
8. 接水时切到后台，确认前台服务通知、设备结算、支付状态和“使用中”页面更新。
9. 连点开始、开启飞行模式、杀进程后重开，确认不会出现第二次解锁或重复支付请求。
10. 验证 BLE 设备、4204、设备故障、定位被拒和登录过期均会阻断并给出提示。
11. 添加第二个账号，切换后确认扫码/解锁使用新账号；切换回来正常。接水进行中不得切换账号。
12. 重命名、删除非当前账号；删除当前账号后自动切到最近有效账号，无其他账号时回登录页。
13. 用失效 token 验证：账号被标记为已失效并回登录页，其他账号可直接切换；失效账号可重登或删除。
14. 在设置页检查头像、昵称、脱敏手机号、账户余额、通用小票（点数/元）、本金/赠送、积分；切换隐藏/显示并重启，确认偏好保留。
15. 飞行模式下进入设置，确认显示上次资产快照与刷新失败提示；恢复网络后手动刷新成功。
16. 打开“账号 → 通用小票明细”，验证店铺总额/本金/赠送、进入店铺后的流水分页、`+/-` 金额与空态；核对一页以上数据，并验证返回键逐级回到店铺列表和设置页。
17. 两个账号分别查看历史与导出 CSV，确认互不混淆；清空历史只影响当前账号。
18. 头像缺失/加载失败时显示首字占位；检查头像请求不携带登录凭证。
19. 在“设置 → 数据”导出 CSV，确认 Excel 打开中文不乱码。
20. 开关“悬浮底栏”，确认两种导航样式、页面切换动画和返回键行为正常。
21. 积分页加载或运行中、资产卡刷新中，刷新/完成按钮应显示禁用态；连点不会产生重复请求。
22. NFC 首次绑定期间按钮显示“正在绑定…”，绑定、跳过与返回互斥，不会重复写入或覆盖新的扫码结果。

### 扫码相机与 NFC 状态

1. “不自动打开相机”默认关闭：首次进入扫码页自动请求相机权限，授权后直接显示预览，与旧版一致。
2. 开启开关后冷启动：进入扫码页不弹权限、不启动相机（可用 `adb shell dumpsys media.camera` 确认），显示待机界面。
3. NFC 已开启：待机显示“NFC 读取已就绪”，点击“扫描二维码”进入预览；NFC 已关闭：底部胶囊显示“NFC 未开启，点此开启”，点击跳系统设置，返回后胶囊自动更新且可读取标签。
4. 无 NFC 硬件：胶囊隐藏，待机提示“设备不支持 NFC”。
5. 待机下相册、手动输入、NFC 均可用；相机启动前不显示手电筒按钮。
6. 待机点击按钮后拒绝权限显示权限引导；去系统设置授权返回后自动进入预览；运行中撤销权限回前台显示引导。
7. 点击启动相机后切换标签页、进出确认页再返回，自动恢复预览；关闭开关后恢复旧行为。
8. 应用前台时用快捷设置开关 NFC，胶囊应实时变化，开启后立即能读标签。

### 账单匹配与小票

1. 用真实账号完成一次有费用的接水，进入历史页。确认列表卡片直接显示原价、逐项优惠、支付优惠、实付，不出现需要再次点击的折叠区。
2. 在官方 App 同一订单详情中核对“实付款”；本应用应显示相同金额，小票抵扣不会从实付中重复扣减。
3. 找一笔确实使用通用小票的订单：确认显示店铺、消耗点数、抵扣金额、本金/赠送。若流水能匹配，再核对流水标题与时间。
4. 找一笔未使用小票的订单：确认不显示小票区块或显示“本单未使用通用小票抵扣”，不出现空金额。
5. 断网后进入已同步过的记录：确认显示上次账单缓存；下拉刷新或点“刷新账单”失败时保留旧账单并提示。
6. 进入 90 天以前的旧记录：确认打开详情后才请求账单；未找到时保留本地记录并标注，不使用“用量”冒充金额。
7. 模拟小票流水查询失败（或使用无流水的订单）：确认仍显示账单内 GOLD 抵扣金额，并标注“店铺流水未匹配/获取失败，以账单抵扣为准”。
8. 切换账号后重复检查：账单缓存和历史一样按账号隔离；删除单条或清空历史后账单缓存一并消失。

### 页面状态与输入

1. 首次进入历史页时制造读取失败：只显示“记录加载失败”和“重新加载”，不出现“还没有接水记录”；恢复网络后重试成功。已有记录时刷新失败应保留列表，并显示错误提示。
2. 通用小票店铺页首次加载失败时只显示加载失败，不显示“共 0 家店铺”；店铺流水首次失败时显示“流水加载失败”，不显示“暂无流水”。
3. 接水进入结束或结算阶段时，页面状态行应显示“正在结束/正在结算”，不再显示“接水进行中”；终态显示对应阶段名称。
4. 登录页手机号键盘使用 `Next` 跳到验证码，验证码使用 `Done` 触发登录；处理中不会重复提交。
5. 手动输入弹窗使用 `Done` 与“识别”按钮的提交条件一致：内容为空不提交，提交后关闭弹窗并清空输入。

### 通用小票充值

真实扣款不在自动化范围内，以下步骤由用户在真机上执行；先使用最小面额。

1. 打开“设置 → 通用小票明细 → 店铺 → 充值”，确认店铺名、余额、面额、赠送与退款说明；核对没有支付宝通道的店铺会禁用“确认充值”。
2. 选择面额并确认弹窗，核对店铺、金额、赠送与“支付宝”；创建订单后核对订单页金额。
3. 已安装支付宝时，在收银台取消支付（`6001`）：确认不显示成功、不扣款，返回后可重新选择。
4. 用最小面额完成真实支付：确认仅在服务端状态确认后显示成功，资产与小票流水自动刷新。
5. 未安装支付宝时：确认 SDK 尝试 H5 收银台；失败时显示“支付结果确认中”，不重复支付。
6. 支付后立即杀进程、断网或返回，再进入同一店铺：确认出现待确认提示，只提供“查询状态”，不会自动发起支付。
7. 切换账号：旧账号的待确认订单不会在新账号下查询或支付；删除账号后待确认订单一并清除。
8. 连点“立即支付”、开启飞行模式、弱网重试：确认不会重复创建订单或重复调起支付宝。
9. 创建订单后、支付中分别点击顶部返回和系统返回：均应弹出“放弃支付？”，取消后留在页面，确认后才返回；支付成功页只保留“查看流水”一个动作。
10. 在支付宝账单与官方订单中核对金额、状态与到账点数；若支付宝已扣款但页面未知，记录订单号并联系官方客服。

### 历史搜索与筛选

1. 搜索设备名、订单号、账单店铺/设备、支付方式、优惠标签、小票备注、错误信息，以及金额/点数；确认能命中，且账号内部 ID 与 `local-` 合成订单号不会命中。
2. 切换时间预设与自定义起止日期，验证今天/7/30/90 天边界、单端日期、跨午夜和本地时区；开始日期不能晚于结束日期。
3. 组合设备、接水结果、账单匹配、支付状态和异常筛选，确认同类多选取并集、不同类之间取交集。
4. 用真实账单验证“已用小票/未用小票”、流水匹配、店铺、本金/赠送构成和小票抵扣金额；确认“未用小票”不包含无账单记录。
5. 输入实付/小票抵扣金额边界、空值、非法文本和最小值大于最大值，确认提示与结果符合预期。
6. 增删条件标签、筛选角标、清除筛选与“清除搜索和筛选”；确认筛选空态和计数“显示 X / 共 Y 条”正确。
7. 切底部页签后筛选保留；切账号或杀进程重启后重置。筛选生效时账单同步仍覆盖全量、删除仍正常、CSV 仍导出全部。
8. 检查统计卡：总花费只包含已支付且已匹配账单的原价，退款/需付/同步失败不计；总用量只加纯数字，带单位后缀跳过；平均单价只用同口径记录，两侧为 0 时显示“—”。
9. 检查统计卡随搜索/筛选/账单同步实时变化，无可见记录时隐藏；核对覆盖率 X/Y 与列表可见数量一致。
10. 检查长设备/店铺列表、弹窗内搜索、键盘弹起、底部弹窗高度、深色模式与返回键行为；自定义日期的系统弹窗应跟随应用明暗模式。
11. 使用 TalkBack 检查复选/单选行播报角色与选中状态；筛选标签的触控区域不小于 48dp，视觉尺寸保持不变。

### 确认页加载与缓存

1. 室内 GPS 无信号：确认页套餐在 1-2 秒内出现；定位未完成时“开始使用”禁用并显示“正在获取定位…”，4 秒内成功或变为“重试定位”，不再出现长时间转圈。
2. 已有定位权限时停留扫码页几秒再扫码：确认页按钮应快速可用（扫码页预热或 5 分钟内存缓存命中）。
3. 首次使用无定位权限：确认页先出现权限引导，不发套餐/支付方式请求；授权后正常加载。
4. 杀进程重开后再次扫描同一设备：套餐应立即出现；后台刷新不改变当前选中项或价格显示。
5. 一键解锁：定位失败时不自动解锁；点击“重试定位”成功后自动解锁一次。
6. 演练模式 + 定位失败仍可进入，lat/lng 显示“未获取”。
7. 断网或关闭定位导致解锁失败：再次扫描应重新加载套餐，不使用旧缓存。
8. 切换账号扫描同一设备不复用另一账号的套餐缓存；删除账号后该账号缓存不可见。
9. 旋转、返回和重复点击“重试定位”不产生重复请求或状态错乱。
10. 开启“跳过设备信息”后扫码与 NFC 均不出现设备信息弹窗，直接进入确认页；从确认页返回后扫码页处于待扫描状态；关闭开关后恢复弹窗。与“一键解锁”同时开启时，已确认设备扫码后自动解锁进入使用页。

### 积分与自动积分

1. 底部导航显示“扫码 / 历史 / 积分 / 设置”，切换与返回键正常。
2. 积分页显示当前账号余额、签到状态、任务列表与日志；切换账号后页面数据随账号更新。
3. 自动积分默认关闭；首次开启弹出风险确认；关闭后启动、回前台、进积分页都不自动发请求，但“立即运行”仍可用。
4. 开启总开关和“启动 App 时检查”，冷启动只自动运行一次；同一天再次启动或进入积分页不重复。
5. 关闭“启动 App 时检查”，启动不自动运行；进入积分页仍会检查一次。
6. 签到成功后当日标记完成；断网导致签到失败时当日不自动重试，恢复网络后可手动重跑。
7. 任务列表加载失败时签到结果仍保留；页面显示错误并允许手动刷新。
8. 遇到验证码任务会跳过；连续两次后停止任务阶段；广告、H5、外部跳转任务不被自动完成。
9. 通知权限关闭时，通知类任务显示“需开启通知权限”，可跳系统设置；返回后任务状态刷新。
10. “直接任务实验”默认关闭；开启后只尝试无扩展、无跳转、通知权限已开启的极少数通知任务。
11. 自动运行中切到后台会取消；切换账号会取消并清空旧账号状态。
12. 日志不包含 token、手机号、请求头或原始响应；清除应用数据后自动积分设置和运行记录消失。

> 积分是否实际到账只能通过真实账号与官方服务验证；JVM 测试不能证明服务端会接受任务完成请求。

## 已知限制

- BLE 解锁未实现：`isBluetooth=1` 的设备会阻断。
- 后付费自动扣款与补缴路径未动态验证；支付未知时提示回原 App 核对。
- NFC 标签格式与绑定策略可能因学校或设备而异。
- 官方服务调整可能导致接口行为变化，需要重新验收。
- 自动化测试只覆盖纯 JVM 逻辑，不包含相机、NFC、定位、前台服务和真实支付。
- 定位的 `LocationManager` 回调、权限弹窗、室内定位耗时、套餐缓存 DataStore 文件与杀进程后的持久化都必须真机验收；JVM 测试只覆盖位置缓存、状态机与缓存排序逻辑。
- DataStore、Android Keystore、SQLite 迁移与 Coil 图片加载无法在 JVM 单测中覆盖，必须真机验收。
- 通用小票的流水 `type`/`subType` 完整枚举、`afterAmount` 语义、分页上限与资产总额口径仍需真实账号复核。
- 账单匹配依赖官方订单详情与店铺小票流水的字段及订单号对应关系，JVM 测试只覆盖解析、金额口径与同步策略；真实账号下仍需验证“实付款”、优惠逐项、GOLD 抵扣与流水的匹配结果。
- 通用小票充值的 JVM 测试只覆盖状态机、参数与结果映射，不包含支付宝收银台、H5 兜底、真实扣款、服务端风控、包名/签名兼容性和订单状态枚举；这些必须用最小面额真机验证。
- 待确认订单依赖 Android DataStore 持久化，杀进程恢复、2 小时过期与删除账号清理需要真机验收。
- 小票流水每次最多读取固定页数；极老或流水很多的店铺可能显示“店铺流水未匹配”，此时账单抵扣金额仍然有效。
- 账单自动同步范围是最近 90 天；更早记录需要打开详情或下拉刷新按需匹配。官方账单字段或状态语义变化可能导致金额/状态展示需要更新。
- 历史搜索与筛选完全在客户端已加载记录上进行，不改变数据库查询或账单同步范围；账单同步完成时，依赖账单的筛选结果会动态变化。
- 时间筛选使用列表卡片显示的 `updatedAt`（记录最后更新时间），不是接水开始时间或账单支付时间；“今天/近 N 天”在页面重组时计算，跨午夜不会主动刷新。
- 筛选状态只保存在内存中，切换账号或进程重启会重置；CSV 始终导出全部记录。自定义日期使用系统 `DatePickerDialog`，已按应用明暗主题选择日间/夜间主题，但控件风格仍可能与 Miuix 页面存在差异。
- 统计卡的总花费是“已支付且已匹配账单的原价”，不是实付；总用量只接受纯数字，带单位后缀会跳过；平均单价只用同口径记录。账单同步进行中，统计会随数据更新而变化。
- 统计没有跨账号或服务端汇总，只针对当前账号、当前筛选结果；未匹配账单和不可解析用量不会被估算或补齐。
- 自动积分依赖官方任务/签到接口；任务列表结构、设备标识校验、验证码触发与积分到账均需真实账号验证，JVM 测试只覆盖分类器和状态机。
- 资产卡片刷新失败时显示的是最近一次成功快照，可能不是实时数据；以官方客户端为准。
