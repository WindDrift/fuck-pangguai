# 测试与验收

本文说明自动化测试范围、真机验收清单和已知限制。核心链路已于 2026-10-24 在真机验证；BLE 与自动扣款仍属于未完成或未动态验证的部分。

## 单元测试

全部测试位于 `app/src/test/`，使用 JUnit 4，不依赖真机。

| 测试 | 覆盖内容 |
| --- | --- |
| `ConfirmControllerTest` | BLE 阻断、定位缺失、演练模式、真实解锁、支付通道绑定、消息超时、一键解锁 |
| `ChannelSelectorTest` | 支付通道选择优先级 |
| `QrParserTest` | 二维码字段解析与异常输入 |
| `QrDecoderTest` | 相机、相册、反色与低对比度二维码解码 |
| `NfcPayloadParserTest` | NFC 标签解析与映射输入 |
| `ScanStateTest` | 扫描状态机与重复结果抑制 |
| `QiekjSignerTest` | 普通签名、风控签名与密钥变化 |
| `ApiModelsTest` | 响应模型与错误封装解析 |
| `SettlementDeciderTest` | 结算阶段与支付结果判定 |
| `WaterDefaultsTest` | 默认套餐、优惠与支付类型规则 |

运行：

```bash
./gradlew :app:testDebugUnitTest
```

测试使用虚拟密钥，不需要配置 `secrets.properties`。

## 静态检查

```bash
./gradlew :app:lintDebug
```

lint 通过不代表真机流程可用；涉及硬件、定位、通知和支付的改动仍需手动回归。

## 真机验收清单

建议在每次较大改动或发版前执行。测试时使用最小套餐，避免产生不必要的费用。

1. 连接设备，确认 `adb devices` 可见；安装 Debug 包。
2. 完成免责声明、短信登录，并验证重启后自动登录。
3. 扫描真实设备二维码，在诊断页确认 `isBluetooth`、故障码、套餐和支付通道。
4. 碰一次 NFC 标签，确认标签解析、首次绑定，以及重启后映射仍然存在。
5. 保持演练模式走一次确认页，核对请求参数、签名是否存在和套餐信息。
6. 关闭演练模式，用最小套餐真实解锁；记录订单号、同步标识和支付单号，核对账单。
7. 接水时切到后台，确认前台服务通知、设备结算、支付状态和“使用中”页面更新。
8. 连点开始、开启飞行模式、杀进程后重开，确认不会出现第二次解锁或重复支付请求。
9. 验证 BLE 设备、4204、设备故障、定位被拒和登录过期均会阻断并给出提示。
10. 在“设置 → 数据”导出 CSV，确认 Excel 打开中文不乱码。
11. 开关“悬浮底栏”，确认两种导航样式、页面切换动画和返回键行为正常。

## 回归范围

### 每次改动

- 单元测试与 lint。
- 受影响页面的手动走查。
- 文档中的命令、链接和版本号。

### 发布前

- 完整真机验收清单。
- Debug 与 Release 各安装一次；确认签名与升级路径。
- 空凭据构建只用于检查编译，不用于发布。
- 确认 CI 的签名与 API 凭据均存在。

## 已知限制

- BLE 解锁未实现：`isBluetooth=1` 的设备会阻断。
- 后付费自动扣款与补缴路径未动态验证；支付未知时提示回原 App 核对。
- NFC 标签格式与绑定策略可能因学校或设备而异。
- 官方服务调整可能导致接口行为变化，需要重新验收。
- 自动化测试只覆盖纯 JVM 逻辑，不包含相机、NFC、定位、前台服务和真实支付。

## 反馈问题时

请附上：

- 应用版本与构建类型（Debug / Release）。
- 设备型号、Android 版本、是否使用 NFC。
- 复现步骤、预期结果与实际结果。
- 脱敏后的错误信息或日志片段。

不要上传完整 token、手机号、订单号、设备完整 JSON 或未打码截图。
