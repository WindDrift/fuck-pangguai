# 调试指南

本文面向开发与排障，介绍 Debug 构建的专属入口和隐藏诊断页。普通用户无需阅读。

## Debug 与 Release 的差异

| 能力 | Debug | Release |
| --- | --- | --- |
| 粘贴 token 登录 | 支持 | 不支持 |
| 演练模式默认值 | 开启 | 关闭 |
| 隐藏诊断页 | 支持 | 支持，但部分内容受限 |
| 请求日志 | 记录最近请求 | 不记录完整请求 |
| R8 / 资源压缩 | 关闭 | 开启 |

Debug 构建默认开启演练模式，是为了避免误触真实解锁。正式使用前需要在设置中关闭。

## 粘贴 token

Debug 构建的登录页和“添加账号”页提供“粘贴 token”入口，用于跳过短信验证码。token 会被加密保存为本地账号并自动切换，生命周期与正常登录一致。

注意事项：

- 只在本机调试时使用，不要将 token 写入脚本、文档或 Issue。
- 删除当前账号会清除该账号的 token；切换账号不会覆盖其他已保存账号。
- Release 构建不显示该入口。

## 演练模式

- 开启时，确认页只展示将要发送的请求和参数，不真实调用解锁。
- 关闭后才会真正创建订单并解锁设备。
- 设置页与诊断页都可以切换，两边共享同一状态。
- 排查参数问题时优先保持开启，确认无误后再关闭。

## 一键解锁

默认关闭。开启后，仍需对同一设备完成过一次确认，后续扫码才会直接解锁。该限制用于降低误操作风险。

如果一键解锁没有生效，先确认：

1. 设置中已开启“一键解锁”。
2. 当前设备此前至少成功确认过一次。
3. 没有停留在演练模式。

## 跳过设备信息

默认关闭。开启后扫码或 NFC 识别成功会直接进入确认页，不再弹出设备信息。与“一键解锁”同时开启时，已确认过的设备可以实现扫码或碰一碰即开。

如果识别后仍停在设备信息弹窗，先确认设置中的开关是否已保存；首次遇到的新 NFC 标签仍会先询问是否绑定，这是独立步骤，不受该开关影响。

## 隐藏诊断页

在关于页连续点击“版本”7 次进入。页面包含：

### 设备探测

展示最近一次扫码得到的设备信息，包括：

- `isBluetooth`：是否为 BLE 设备。为 1 时当前版本会阻断解锁。
- `deviceErrorCode`：设备故障码，例如 4204。
- `payment`、`payModel`、`tradeMain`：设备支付相关状态。
- `orgId`、`shopId`、`payTypes`、`extAttr` 等辅助字段。
- 原始设备 JSON，可复制用于比对。

诊断页只展示最近一次识别结果。切换设备后需要重新扫码。

NFC 标签管理已移至「设置 → 使用 → 管理 NFC 标签」，诊断页不再提供映射删除入口。

### 请求日志

Debug 构建会记录最近的网络请求（最多 100 条），包括方法、URL、状态码、耗时、请求头、请求体和响应。可复制单条请求为 cURL。

日志会对登录凭证、手机号、验证码与定位等常见敏感字段打码，但响应内容、设备标识或订单号仍可能包含隐私信息。**分享前必须逐项检查并手动打码**，不要直接上传完整日志。

Release 构建不安装请求日志拦截器，因此诊断页只显示有限的设备信息。

## 典型排障流程

1. 保持演练模式，扫码并进入确认页。
2. 在诊断页核对设备类型、故障码、支付字段和原始 JSON。
3. 查看请求日志，确认参数与预期一致。
4. 检查定位权限与位置是否可用。
5. 关闭演练模式，用最小套餐做一次真实解锁。
6. 记录订单号与状态变化，核对设备结算和支付结果。

涉及 NFC 时，再确认标签解析结果与映射是否指向同一台设备。不同学校的标签格式可能不同，必要时重新绑定。

## 安全提醒

- 诊断页和请求日志仅用于本机排障，不要截图上传未脱敏的手机号、token、订单号或设备标识。
- 不要把诊断页的完整 JSON 或 cURL 粘贴到公开 Issue。
- 不要在 Release 构建中依赖调试入口完成日常操作。
