# 调试指南

本文面向开发与排障，介绍 Debug/诊断构建的专属入口、持久化诊断日志、接水全链路耗时与导出方式。普通用户无需阅读。

## 构建类型差异

| 能力 | Debug | 诊断（diagnostic） | Release |
| --- | --- | --- | --- |
| 粘贴 token 登录 | 支持 | 不支持 | 不支持 |
| 演练模式默认值 | 开启 | 关闭 | 关闭 |
| 隐藏诊断页 | 支持 | 支持 | 支持 |
| 持久化诊断日志 | 支持 | 支持 | 支持（默认开启） |
| Debug 级事件与更大响应预览 | 支持 | 支持 | 不支持 |
| 最近请求 cURL（仅内存） | 支持 | 支持 | 不支持 |
| R8 / 资源压缩 | 关闭 | 开启 | 开启 |
| 正式签名 | 否 | 是 | 是 |
| 版本名 | `<version>` | `<version>-diagnostic` | `<version>` |
| 应用名 | 原名 | 原名（诊断） | 原名 |

诊断包与正式版同包名、同 versionCode、同正式签名，可与正式版互相覆盖安装。覆盖安装会结束应用进程；接水或支付进行中请勿安装。

Debug 构建默认开启演练模式，是为了避免误触真实解锁。正式使用前需要在设置中关闭。

## 粘贴 token

Debug 构建的登录页、添加账号页和诊断页提供“粘贴 token”入口，用于跳过短信验证码。token 会被加密保存为本地账号并自动切换，生命周期与正常登录一致。

注意事项：

- 只在本机调试时使用，不要将 token 写入脚本、文档或 Issue。
- 删除当前账号会清除该账号的 token；切换账号不会覆盖其他已保存账号。
- Release/诊断构建不显示该入口。

## 演练模式

- 开启时，确认页只展示将要发送的请求和参数，不真实调用解锁。
- 关闭后才会真正创建订单并解锁设备。
- 设置页与诊断页都可以切换，两边共享同一状态。
- 排查参数问题时优先保持开启，确认无误后再关闭。

## 一键解锁

默认关闭。开启后，仍需对同一设备完成过一次确认，后续扫码才会直接解锁。该限制用于降低误操作风险。

如果一键解锁没有生效，先确认：

1. 设置中已开启“一键解锁”。
2. 当前设备此前至少成功确认过一次。
3. 没有停留在演练模式。

## 跳过设备信息

默认关闭。开启后扫码或 NFC 识别成功会直接进入确认页，不再弹出设备信息。与“一键解锁”同时开启时，已确认过的设备可以实现扫码或碰一碰即开。

如果识别后仍停在设备信息弹窗，先确认设置中的开关是否已保存；首次遇到的新 NFC 标签仍会先询问是否绑定，这是独立步骤，不受该开关影响。

## 隐藏诊断页

在关于页连续点击“版本”7 次进入。页面分为“概览 / 事件 / 接水 / 设置”四个标签。

### 概览

- 日志开关、存储占用与条数、分享/保存诊断包。
- 当前进行中的接水 trace 与阶段进度。
- 最近 3 次崩溃的堆栈，可复制为 JSON。
- 设备探测：最近一次扫码得到的设备信息，包括 `isBluetooth`、`deviceErrorCode`、`payment`、`payModel`、`tradeMain`、`orgId`、`shopId`、`payTypes`、`extAttr` 与原始设备 JSON。
- Debug/诊断构建的最近请求与 cURL 视图（仅内存，最多 100 条）。
- 演练模式开关；Debug 构建额外显示 token 导入。

NFC 标签管理已移至「设置 → 使用 → 管理 NFC 标签」，诊断页不再提供映射删除入口。

### 事件

- 搜索名称、消息、类别、traceId 与字段值。
- 按级别（Debug/Info/Warn/Error）、类别（应用/账号/扫码/设备/确认/接水/网络/历史/积分/小票/更新/崩溃）和时间范围筛选。
- 默认显示 200 条，可加载更多；显示“已显示 X / 匹配 Y（共 Z）”。
- 点击展开字段与脱敏响应预览；可复制单条事件 JSON；带 traceId 的事件可跳转到“接水”页。

### 接水

一次接水按 7 段记录：

1. 扫码识别（仅二维码解码耗时；相册只计解码，手动/NFC 为 0）
2. 设备解析（扫码/详情两次请求）
3. 确认页就绪（缓存命中为 0 次请求，否则套餐+支付方式两次）
4. 解锁（包含预绑定/补绑、unlock 请求与 msgSync 轮询）
5. 出水确认（首次 `workStatus==2` 或 `amount>0`）
6. 结束接水（用户结束或设备结束；记录用水时长与结束操作耗时）
7. 结算支付（结算单、afterPayCreate 与 pay_status 轮询）

页面支持按设备/goodsId/traceId、结果与时间筛选。统计卡按阶段显示成功/失败/放弃/进行中、平均与最大耗时、参与 trace 数与平均尝试次数；未到达的阶段不计入平均。每条 trace 可展开查看阶段结果、错误与字段。

总耗时是墙钟全链路（含用户操作间隔与用水时长），不等于各阶段耗时之和。进行中的 trace 显示“进行中”；进程中断或超过 10 分钟未更新的 trace 在下次启动时标为“中断”。

### 设置

- 日志开关、保留天数（1–30 天，默认 7）、存储上限（1–100 MB，默认 10）。
- 分享/保存诊断包、清空全部诊断日志（需确认）。
- 演练模式；Debug 构建显示 token 导入。
- Debug/诊断构建提供“写入测试崩溃”，用于验收崩溃记录。

保留策略先按天数删除旧日文件，再按总大小删除最旧文件；当天文件不会被大小清理删除。清空只删除诊断目录，不影响账号、历史、设置或其他缓存。

## 日志内容与脱敏

记录的内容：

- 应用启动（版本/buildType）、前台/后台、登录/切换/退出、会话失效。
- 扫码来源、解码耗时、设备解析、NFC 绑定、套餐缓存命中/刷新、定位结果。
- 确认页 Ready/Blocked/Error、缓存来源、预绑定/补绑、unlock、msgSync 次数、一键解锁、演练、放弃。
- 会话创建/恢复、每次 waterSync 摘要、出水确认、用户结束、设备结束、故障、结算决策、afterPayCreate、支付结果与终态。
- 网络请求摘要：方法、路径、状态码、耗时与脱敏响应预览；核心请求成功记 Info，轮询类成功记 Debug，失败记 Warn/Error。
- 未处理异常堆栈与崩溃时的当前 trace。

不记录的内容：

- 请求体、请求头与查询参数。
- 原始二维码、SN/IMEI、坐标、token、手机号。
- 逐帧相机数据与逐条历史明细。

响应中的 `token/phone/realName/idCardNo/imei/sn/qrCode/lat/lng/password/verifyCode` 等字段会替换为 `<redacted>`；非 JSON 响应不保存原文。设备只保留名称与 goodsId，账号只保留本地 localId；订单号、msgId、identify 等保留用于关联，导出前会再次提示。

请求体与请求头不会落盘；cURL 视图只在 Debug/诊断构建的内存中保留，退出进程即丢失。

## 导出

导出物是单个 ZIP，包含：

- `diagnostics.txt`：人类可读的元信息、全量统计、当前筛选统计、逐条 trace、事件与崩溃。
- `diagnostics.json`：同内容的机器可读版本（`schemaVersion`、版本、设置、筛选、计数、统计、事件、trace、崩溃）。
- `README.txt`：字段说明、脱敏规则与隐私提醒。

导出使用保留期内的全部日志，而不是仅当前筛选；筛选条件会写入导出物。分享与保存前都会弹出隐私警告，因为日志可能包含设备名称、goodsId、订单号与脱敏响应片段。

- 分享：ZIP 写入应用缓存目录，通过 `FileProvider` 调用系统分享。
- 保存：通过系统文件选择器保存 ZIP。

缓存最多保留 5 个最近导出文件。

## 崩溃

- 未处理异常会同步写入崩溃记录，包含线程、异常、完整堆栈、当前 trace 与版本信息。
- 下次启动后可在诊断页“崩溃记录”查看最近 3 次堆栈，并复制完整 JSON。
- 崩溃记录也会进入 TXT/JSON 导出。
- 应用不会自动上传日志或崩溃；崩溃记录在日志开关关闭时仍会保留，便于定位问题。

## 典型排障流程

1. 保持演练模式，扫码并进入确认页。
2. 在诊断页核对设备类型、故障码、支付字段和原始 JSON。
3. 在“事件”页查看扫码/设备/确认/网络事件，确认参数与预期一致。
4. 检查定位权限与位置是否可用。
5. 关闭演练模式，用最小套餐做一次真实解锁。
6. 在“接水”页核对 7 段耗时、出水确认、结束与结算结果；必要时导出 ZIP 分享给维护者。
7. 记录订单号与状态变化，核对设备结算和支付结果。

涉及 NFC 时，再确认标签解析结果与映射是否指向同一台设备。不同学校的标签格式可能不同，必要时重新绑定。

## 安全提醒

- 诊断页和诊断包仅用于本机排障，不要截图上传未脱敏的手机号、token、订单号或设备标识。
- 不要把诊断页的完整 JSON、cURL 或诊断包粘贴到公开 Issue。
- 不要在 Release/诊断构建中依赖调试入口完成日常操作。
- 安装诊断包前确认没有进行中的接水或支付；覆盖安装会杀进程。
